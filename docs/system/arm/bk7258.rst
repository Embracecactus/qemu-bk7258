BK7258 diagnostic machines (t5_board, t5ai_core, aidk_ai_toy)
==========================================================

This is a downstream, AI-assisted local experiment. It is not an upstream
QEMU contribution and must not be submitted upstream under QEMU's current
code-provenance policy. Its base is the existing fork commit
``81ce3a87737aa50716c42db8886082d12783e0a1`` (11.1.50); no upstream history
was rewritten and no stable-release compatibility is claimed.

The three machine names identify the project's physical boards. They currently
instantiate the same shared diagnostic SoC, with distinct user LED/key wiring
for the revisions below. Other board peripherals are not yet implemented.
Listing all three names does not establish complete board support.

``hw/arm/bk7258.c`` owns the shared SoC, register map, physical cores and
on-chip devices. ``hw/arm/bk7258_boards.c`` owns the machine registrations
and the external NOR choice, its host drives and explicit diagnostic image
loading. The loader is still an explicit diagnostic handoff, not a hardware reset-ROM
implementation. Firmware partition/role policy is not part of the SoC.

The board creates ``/machine/nor`` and connects the SoC's ``flash-nor`` QOM
link to the controller. The controller requires an already-realized memory
part and queries its capacity and JEDEC ID; it does not construct the part or
choose its identity. Link type checks and the standard qdev realization guard
reject changing/unsetting the connection on a live machine. All three board
models still explicitly choose the same bounded GD25WQ64E experiment part;
this separation does not establish their physical BOMs or add other NOR
variants. Diagnostic logical-XIP entry keeps that object but does not map the
physical controller/XIP view, preserving the existing loader/error contract.

Chip-first validation status
----------------------------

Development order is the reusable chip/SoC contract first, sourced board
connections second, and complete external firmware acceptance last. Passing a
small diagnostic is evidence for its named hardware path, not completion of
BK7258 as a whole. The independent QEMU tests are the chip/board gate; no
OpenVela source or profile changes are required for that gate.

For each added chip block, require source-backed access/reset/clock/IRQ
semantics and native positive/negative tests: mask then unmask, W1C, disabled
or lost clocks, invalid access, reset during pending work, wrap/overflow and
error propagation where applicable. Keep unsupported cases explicit; do not
return fabricated completion to move firmware past them. Timing abstractions
and unmeasured edge behavior must be named separately from hardware facts.

The board gate adds only evidenced external wiring and tests correct/incorrect
pins, polarity, release/bias and reset behavior. Its current LED/key subset is
listed below; the remaining fitted devices do not become supported merely
because the machine has the board's name. Complete OS/product boot, update
flows and performance remain a later external-consumer acceptance stage.

P0 closure means the explicitly enumerated functional baseline and its evidence
are complete, not Wi-Fi/BT/media throughput, analog fidelity, security
certification or complete chip coverage. Those absent blocks remain visible
in the capability inventory and cannot be marked supported by omission.
When source material cannot determine a required behavior, record the gap and
keep that gate open while implementing independent, evidenced portions.

After the chip baseline, each board gate requires an identified hardware
revision, sourced external parts/pins and wiring tests, including absent or
incorrect devices and reset/contact behavior. External OS/product firmware
acceptance follows those gates as a separate consumer test; its boot success
cannot replace a missing chip or board contract.

Remaining P0 evidence collection
--------------------------------

The current independent model is a partially implemented chip, not a closed
P0 baseline. A review of the pinned SDK and manufacturer documents found no
sufficiently specified new CPU-variant, reset-reason or security-enforcement
slice. The following evidence would resolve concrete decisions; adding
identity constants, R7A snapshots or permissive security stubs would not.
Prefer existing captures and public revision-specific vendor documentation.
This checklist does not authorize or require device programming, reset,
core halt/release, selector writes or changes to debug/security access.

**Per-core identity.** The manufacturer identifies STAR-MC1, double-precision
FPU, DSP, TrustZone and 16-KiB ITCM/DTCM. Generic CMSIS presence flags do not
specify each core's implementation. QEMU's current Cortex-M33 supplies its own
MIDR 0x410fd213, 16 MPU regions, 8 SAU regions, MVFR0 0x10110021 and no cache
in CLIDR. Renaming it cannot establish STAR or AP cache conformance.

Where a physical core is already accessible through an authorized read-only
capture path, record silicon/package revision, physical core number, privilege,
security state and boot stage with these aligned 32-bit metadata reads. The
pinned ``core_star.h`` defines the feature/identification fields as read-only;
the optional selector below is R/W. These definitions do not promise access
from every state:

* CPUID at 0xE000ED00; feature IDs at 0xE000ED40 through 0xE000ED70.
* CLIDR/CTR at 0xE000ED78/0xE000ED7C.
* MVFR0/1/2 at 0xE000EF40/0xE000EF44/0xE000EF48.
* MPU.TYPE at 0xE000ED90 and SAU.TYPE at 0xE000EDD4, the latter with the
  corresponding Secure access context.
* Optionally, the existing R/W CSSELR selector and read-only CCSIDR pair at 0xE000ED84/0xE000ED80.
  Do not change CSSELR; this pair describes only the currently selected cache.

The vendor still needs to specify per-core revision, FPU precision, MPU/SAU
counts, cache geometry/maintenance, TCM enable/reset and debug configuration.
These fields should be collected independently for all three physical cores;
a CPU0 observation is not evidence of CPU1/2 geometry.

**Reset lifecycle.** The SDK's Secure map places AON R0 at 0x44000000, R2
at 0x44000008 and R7A at 0x440001e8. R0 carries software reason tags and uses
a keyed commit; startup reads R7A then updates R0's reason-tag fields to
POWERON. R7A's
generated struct calls its bits reserved. Request a vendor definition of
R0-to-R7A capture trigger/order, defaults, read/clear/write effects and retained
domains. Read side effects are not established, so repeated R7A probing is
not a prescribed read-only experiment. Likewise, address aliases do not prove
access permission. Obtain the reset-domain matrix for POR, brownout, AWDT,
DWDT configurations, system/core reset, shutdown and deep-sleep wake,
including retention of RTC, SRAM/TCM, core controls and security state.
Existing startup traces must identify their capture stage; post-init tags are
not an untouched reset snapshot.

**Security attribution.** Verified base addresses are PRRO 0x41040000 and
MPC PSRAM/Flash at 0x41100000/0x41200000, with SRAM0..5 at
0x41210000..0x41260000. A base address is not a verified readable-register
inventory. The SDK's PRRO/MPC/PPC CSV files describe boot configuration, not
silicon reset policy. ``ppc.py`` demonstrates how PPC policy and PRRO
maps/defaults generate configuration data; it is not the MPC generator.
Request IDAU alias/attribution rules, PRRO/PPC polarity/access/lock/reset
semantics, MPC granularity/limits/window behavior, CPU/DMA attribution and
denied-access responses/IRQs. Banked-window captures would need their existing
selector and security/master context, with read side effects confirmed first.
Do not probe unidentified windows or change selectors. OTP, keys, ROM contents
and production memory dumps are not needed for these decisions.

**Other blocked contracts.** Obtain the actual package/board revision and BOM
for fitted NOR/PSRAM; existing startup logs may help but fallback success is
not identification. Resolve the PSRAM/DPLL boundaries below, PWM counter
inventory/polarity and the actual TIMG/PWM CLK32 nets. UART DMA needs data-lane,
packing/flush and request-handshake definitions; SPI16 needs capacity/count and
subword timing definitions. Register configuration alone does not measure a
clock or waveform. Do not silently add pinmux writes, frequency-output setup
or resets to a passive collection request.

Relevant pinned sources are the CP/AP ``armstar.h`` and ``core_star.h``,
``reset_reason.c``, ``aon_pmu_ll.h``, ``aon_pmu_struct.h``, ``aon_pmu_hal.c``,
``reg_base.h``, ``boards/bk7258/{regs,csv}`` and
``tools/env_tools/beken_utils/scripts/ppc.py``. Manufacturer datasheet sections
4.3/4.4 and the CPU description constrain these questions but do not answer
all of them. Complete board and external-firmware acceptance remain later
gates; the existing green native tests do not remove these evidence blockers.

-----------------

The three thin board classes share the SoC but connect distinct external
endpoints. These are partial board models, not complete peripheral inventories:

   * - ``t5ai_core``
     - P9 active-high
     - P29 active-low

   * - ``aidk_ai_toy``
     - P40 active-high
     - P8/KEY3 active-low

The LED uses QEMU's existing ``led`` device. Green for T5/Core is a visualization
choice, not a verified component color; the AIDK LED1 net drives red LED3 in
the source schematic. AIDK P9 is the motor control, not this board's LED.
Other keys, reset-button circuits, motor, LCD, camera, audio, storage connectors
and native USB remain unconnected. T5 P1's shared UART alternative function is not wired
to the LED yet; GPIO-mode checks must not be presented as UART waveform tests.

The machine property ``user-key-pressed`` controls the ideal contact. For
example, ``-M t5ai_core,user-key-pressed=on`` starts with it held. At runtime,
QMP can set the boolean property on ``/machine``; ``user-led-on`` is read-only
and observes the connected LED device. Holding a key across a system reset
preserves the external contact while the SoC resets its GPIO configuration.
There is no key debounce, RC charging, ADC conversion, supply or contention
model. The T5 ADC_KEY input is covered only as a digital contact endpoint.

The SoC's named ``gpio-in`` lines accept 0/1 for an external level and -1 to
release the external source. A released AIDK key therefore follows the GPIO's
configured pull, rather than always reading high. Values outside -1/0/1 are
rejected without changing the pin. An un-driven, unbiased digital input reads
zero in this functional model; that is not a physical floating-voltage claim.

Implemented slice
-----------------

* Three Cortex-M33 CPUs with separate NVICs (64 inputs, three priority bits)
  and separate 16-KiB ITCM / 16-KiB DTCM. CPU0 starts; CPU1 and CPU2 are held.
* Shared 640-KiB SRAM and all four address aliases below.
* Two explicit entry modes selected by the board loader: ``-kernel`` uses
  diagnostic logical XIP (ELF, or the standard Arm loader's raw-image fallback);
  otherwise an 8-MiB physical NOR provides CRC-framed XIP and controller MMIO.
  The physical device is present even without a host file: its erased array
  and NV status are then process-local. A logical kernel cannot be combined
  with NOR drives, so it cannot silently shadow the controller's byte array.
  Diagnostic mode deliberately omits controller MMIO; it is not a physical
  Flash boot claim. The SoC does not infer its topology from host-file presence.
* A bounded GD25WQ64E NOR model (JEDEC C86517, an explicit part choice, not
  board identification), 32-byte controller read/program FIFO, asynchronous
  status/ID/erase commands, real protection ranges and persistent array/NV
  status. Logical XIP removes each 2-byte CRC trailer from 32-byte payloads
  and faults on bad CRC. Controller reads and secure/NS XIP share one array.
* Three functional UARTs: bounded TX/RX queues, byte-frame TX timing,
  threshold service, baud-derived RX-idle completion and TX-finish status,
  W1C acknowledgement, and per-CPU interrupt routing.
  Connect UART0/1/2 with the first/second/third ``-serial`` option.
  SYS+0x30 bits 2/10/11 gate their functional clocks. SYS+0x20 uses divider
  fields 8:9/11:12/14:15 (divide by 1/2/4/8) and source bits 10/13/16
  (XTAL/APLL). The fixed 26-MHz XTAL is available; APLL generation is absent,
  so selecting APLL logs the omission and supplies no clock. The UART model
  receives a QEMU clock rather than assuming every source is always 26 MHz.
* SYS core control and interrupt enable/status registers. Reset release samples
  the vector address; changing vector bits while running does not reset a CPU.
  Halt/power gates preserve CPU state. Changes run in target-CPU order.
  Unsupported SYS reads/writes return a bus error as well as a diagnostic log.
  This strict model policy prevents an absent device-ID or ignored status write
  from appearing to succeed; it does not claim the silicon faults on every
  unmodeled register. Guest tests check the actual HardFault exception, precise
  BusFault status and fault address for secure reads and NS-alias writes.
* Native Cortex-M33 SysTick exception delivery. Core timing inputs remain
  26 MHz unless the experimental finite-clock option below is enabled.
  SYS+0x40 bits 29/30/27 gate each core's selected LPO reference.
  Gating preserves timer count; changing an unselected source is inert.
* AON watchdog key/reload/stop and timed system reset. APB watchdog clock
  gate/divider, key/reload/stop and real CP (physical CPU0) NMI delivery;
  the NMI handler, rather than the device, decides whether to reset.
  AWDT follows ROSC/32, while DWDT follows the selected LPO through its
  SYS divider and gate. Selecting an absent LPO stops DWDT but leaves AWDT
  running; disabling ROSC stops AWDT even when DIVD still clocks DWDT.
* AON PMU R0/R1/R2, keyed retention commit, sleep/wake configuration readback,
  and a selectable chip ID. Default 0x24940610 is the SDK MP-I revision choice,
  not a claim that every physical board has this revision. Override with
  ``-global bk7258-aon.chip-id=...`` when using another documented revision.
* AON R41 bits 0:1 select the LPO clock: 0 is the nominal 26-MHz-derived
  32-kHz source, 1 is the external 32-kHz input, and 2 is ROSC. Each input is
  a QEMU clock; source loss propagates through the mux and the independent
  per-core SysTick gates. ANA5 bit14 disables ROSC after the modeled analog
  transfer completes. The SoC exposes ``lpo-external`` as a clock input for
  future board wiring. These three board models currently leave it unconnected,
  so selecting it stops the reference instead of inventing a fitted oscillator.
  The AIDK schematic shows X2/C16/C17 greyed out, without an explicit ``NC``
  label beside them. That drawing alone does not verify whether a physical
  assembly fits the 32.768-kHz source. Leaving this input unconnected on all
  three models is a conservative diagnostic choice, not an inventory claim.
  Selecting encoding 3 logs an unsupported case and supplies no clock. This is
  a conservative model policy, not a measured reserved-encoding response.
* 56 digital GPIOs: active-low output enable, input/pull state, retention lock,
  edge/level IRQ55, per-pin IRQ masking and W1C. Named GPIO inputs/outputs can
  connect board devices. SYS GPIO mux registers retain configuration; alternate
  peripheral functions are not connected to physical pads yet.
* AON RTC at 0x44000200 / 0x54000200: one 64-bit LPO counter, 64-bit upper
  and tick thresholds, staging/synchronized readback and IRQ54. The counter
  is read-only; ``cnt_stop`` pauses it and ``cnt_reset`` holds it at zero.
  Native guest code verifies real exception 70 and a missing-route failure
  while an independent CPU-clock SysTick enforces the test deadline.
* Analog-register transactions: writes become visible after a virtual 1 us
  transfer and clear the per-register busy bit at SYS+0xe8. This is a functional
  transaction latency, not measured analog settling. Writes while busy are
  rejected. The selected SDK CP/AP defconfigs disable
  CONFIG_ANA_REG_WRITE_POLL_REG_B; the alternative SYS+0x2c busy view is absent.

* CKMN measurement at 0x448a0000 (alias 0x548a0000), IRQ21: configured
  RC32K window cycles are timed against an explicit ideal 32,000-Hz ROSC
  input; digital 26 MHz reference cycles produce a latched 20-bit count.
  For example, 64 ROSC cycles take 2 ms and count 52,000 reference cycles.
  Completion is latched under masking and acknowledged W1C; reset/disable
  cancel the operation. ANA5 bit14 powers down the measured source.
  Stable-clock windows are supported. A source change invalidates an active
  window without success; software must disable/rearm. Zero windows, stopped
  clocks and overflow do not fabricate completion. Fractional reference
  cycles round down, and completion is one-shot until software rearm. These
  edge/rounding choices are explicit functional abstractions, not measured
  synchronizer timing. Clock correction/loss-detection/autoswitch dynamics,
  physical ROSC tuning, and device ID/version probes remain unsupported.

* Native MBOX0 v2 at 0x41000000 / 0x51000000: three channels partition eight
  shared slots. TID writes enqueue two opaque words and source channel; SID
  reads pop into RX latches. Full/empty/count derive from the real queues.
  Per-core secure/nonsecure bus views enforce physical channel ownership.
  Each channel drives only its own CPU's IRQ63 and SYS high mask/status bit31.
  Firmware, not QEMU, interprets shared-memory pointers, ACKs or SMP commands.
  Tests execute actual CP/CPU1/CPU2 interrupt-driven exchanges and illegal
  cross-core TID/SID operations under protection.

Diagnostic choices are deliberately explicit: UART TX/RX capacity is 128
queued bytes per direction, matching the datasheet FIFO depth, but FIFO-mode
selection is unidentified. The model uses an always-buffered diagnostic
assumption; it does not claim the datasheet's FIFO-disabled power-on mode.
Interrupt
route masks reset to zero, CPU1 control resets to 0x2 and CPU2 to 0xa. These
reset defaults are an emulator boot contract, not measured power-on defaults.
External SysTick routes start enabled, UART functional clocks start gated,
watchdogs start disarmed, and GPIO pads
start output-disabled with pull-down. AON retained state survives warm reset;
this is not a power-loss persistence model. AON watchdog periods use ROSC/32
(nominal 1 kHz), APB uses LPO / {2,4,8,16}. Clock interruption preserves the
remaining count rounded up to a whole watchdog tick; sub-tick phase is not
retained. Oscillator tolerances, undocumented invalid-key behavior, PMU R2's
selective reset domains and secondary reset escalation are absent.
The APB watchdog's implemented MMIO remains its global control at +0x08
and keyed period at +0x10. Other reads/writes now return a transaction error
instead of read-zero/ignored-write behavior after a log message. Six native
Cortex-M33 cases check an unmodeled identity read and NS-alias status write
on all three machines, requiring a precise BusFault and matching BFAR.
This is a strict model boundary; it does not claim that physical watchdog
identity/status registers fault, or change the supported key/expiry behavior.
The AON watchdog exposes only its existing single keyed word.

UART idle detection uses its selected input clock/(baud divider+1) and
32/64/128/256 bit-times. Gating or loss of the selected source pauses the
remaining source cycles, rounded up to a whole input-clock cycle; recovery
uses the new input rate. Draining RX, disabling RX or reset cancels the idle
window; baud/FIFO reconfiguration restarts it. IRQ status remains W1C.
Register access and latched IRQ state
remain available while the functional clock is gated. TX reports no write-ready
or new completion with a stopped clock; writes while stopped are ignored.
Already queued TX and the pending shift retain their remaining source cycles. Host chardev backpressure
retains bytes outside the device until RX is clocked; this is a logical stream
abstraction, not physical serial-line capture or framing across a clock loss.
Unknown UART register reads and writes, including unmodeled device IDs and
writes to FIFO status, return a transaction error. Guest tests require a
precise escalated BusFault and matching BFAR on all three UARTs and their
nonsecure aliases. This is the same strict diagnostic policy used for SYS:
it exposes missing implementation instead of silently returning zero, and
is not a claim that silicon faults on its valid identification registers.
The 128-byte RX capacity and count/full/empty view are bounded and tested,
including ring wrap and threshold boundary. Host chardev backpressure retains
a 129th byte outside the full FIFO; it must arrive in order after space is
freed. This does not implement physical overflow, RX line errors or the
unidentified FIFO-mode-enable control mentioned by the datasheet. Threshold
status reasserts while the modeled level remains high and stays latched
until acknowledged after draining. Reset discards queued RX bytes and
cancels their idle deadline.

RX applies CONFIG bits4:3's 5..8-bit data width when the character frontend
delivers a complete character. The FIFO stores that character zero-extended
to a byte; subsequent format changes do not reinterpret already accepted
entries. A host byte held outside a full or stopped receiver uses the width
active when it is eventually accepted. This is the stream model's character
representation, not a measured guarantee about silicon's unused FIFO bits.
It does not simulate an external transmitter's mismatched framing or parity.

TX has a bounded 128-byte queue and one separate active shift byte. The latter
is a functional inference from the SDK's ``fifo_count + 1`` drain estimate,
not a measured internal implementation. FIFO count/full/empty exclude that
active byte, so empty alone does not mean the transmitter has finished.
Write-ready requires a live source, released global reset, TX enable and a
free queue slot. A write into a full queue returns a transaction error without
changing its contents; this is a strict model policy, not a silicon-overrun
claim. No host byte is emitted until its frame expires. Host output uses
QEMU's synchronous character frontend and may wait for host backpressure;
this does not model a physical RTS/CTS signal or guarantee nonblocking host I/O.

Frame duration is ``(1 + data_bits + parity_enable + stop_bits) * (divider+1)``
input cycles, with 5..8 data bits and one or two stop bits. Data is masked to
the selected width. Data/format/divider are sampled when a character enters
the shifter; changing configuration affects the next character. This is a
byte-stream framing abstraction, with no parity waveform or bit-error model.
The frame timer uses the shared bounded cycle accounting and pauses on clock
loss. TX_FINISH (bit5) latches only after the last pending character completes;
starting another burst does not acknowledge an earlier finish. TX service
(bit0) latches when queue count is strictly below the programmed threshold;
threshold zero generates no service condition. W1C immediately reasserts an
eligible service level, which is an explicit level-to-latch model policy.

The SDK ``uart_hal_flush_fifo()`` disables then re-enables each direction.
The compatible model policy clears each queue on that direction's falling
enable edge, cancels its pending timing, and preserves existing IRQ latches.
TX cancellation discards an undelivered character atomically; physical partial
bits are outside the stream contract. Ordinary clock gating pauses rather than
flushes. Global reset and full machine reset cancel both directions and clear
status. Independent native qtests cover capacity/ring order, all frame-length
combinations and extreme baud dividers, active-frame configuration changes,
threshold/W1C and all three CPU routes, stopped/missing clocks, directional
flush and reset cancellation. Precise full-FIFO BusFault tests establish only
the strict model boundary, not a hardware bus-fault guarantee.

The standalone guests explicitly enable UART0's clock and preserve it when
enabling other peripherals. No external firmware source changes are required.
Flow/wake
configuration has masked readback, but enabling physical RTS/CTS or sleep-wake
signaling emits an unsupported warning. DMA, physical RX line errors and
pad-level serial bitstreams are not modeled. Core clocks remain fixed by
default; the explicit experimental option below implements selected digital
clock configurations. PMU power fields still retain configuration only; no
PLL lock, calibration completion, rail transition or DVFS success is faked.

The LPO mux resets to encoding 0 as part of the existing diagnostic R41 reset
contract, not a measured cold/warm silicon reset value. DIVD and ROSC both use
the SDK's nominal 32,000-Hz timebase; the physical divider ratio, jitter,
switching latency, oscillator startup and sleep-entry ``halt_lpo`` sequencing
are not modeled. LPO currently feeds SysTick references, RTC, the APB watchdog and the
modeled timer CLK32 path; other fan-out remains unimplemented. Native qtests
read QEMU's existing read-only clock-period property to verify source loss,
recovery, all three independent gates and reset cancellation. External-source
presence/frequency is a board input, not a firmware-specific success setting.

Pending-operation clock accounting
----------------------------------

UART RX-idle, SPI words, I2C operations, DMA beats and watchdog countdowns
recover their remaining whole source cycles from the original arm-time
budget. They reconstruct the arm anchor using the saved budget/rate and
rounded nanosecond deadline, then subtract elapsed whole source cycles.
They do not convert the rounded deadline directly back into cycles: doing
that would round twice and could add a cycle on every same-time gate toggle.
Fractional progress is still discarded at a clock-source change under each
model's documented policy; that does not permit creating whole cycles when
no virtual time elapsed.

The shared helper handles overdue timers as zero remaining work and covers
bounded 32-bit cycle budgets without overflowing intermediate arithmetic.
Watchdog scheduling also checks the representable virtual-time horizon,
matching the other finite-operation timers; an unrepresentable deadline
must not wrap around into an immediate reset.
Its registered unit tests run without a machine or socket. They check known
26-MHz rounding edges, zero-time rearming, the representable time horizon,
and 100,000 exact-rational reference inputs. Native hardware qtests separately
verify UART/SPI/I2C completion at the correct deadline after repeated gate
toggles and after nonzero elapsed time. DMA's fixed HCLK currently makes its
pause correction defensive; a mathematical test is not a claim that a
silicon DMA clock gate or its missing clock-tree wiring was implemented.

PWM counter/compare boundaries
------------------------------

This is the counter/compare core of the legacy paired-channel PWM register
interface, not PWM waveform or pad emulation. Two units are mapped at
``0x458a0000``/``0x458f0000`` and their nonsecure aliases. Each exposes the
three legacy TIM1/2/3 register sets used by the SDK's selected V1PX driver.
The IRQs are physical IRQ5 and IRQ43 (high-bank bit11), respectively.
SYS+0x30 gates3/12 and SYS+0x20 source bits18/19 select their clocks.
Only encoding1, XTAL, is connected. Encoding0, CLK32, is deliberately
unconnected until that net's topology is established; it supplies no clock.
The general-timer model's named CLK32 assumption is not silently extended.

The first slice implements up-counting, divide-by-1..256 per legacy timer,
32-bit ARR with period ARR+1, three compare registers per timer, preload/
shadow readback, software update, mask/W1C and reset cancellation. Nonzero
compares are restricted to 2..ARR. Zero means an unused compare in this
bounded contract. Compare1 and ARR+1 are not accepted in an active counter.
The SDK explicitly avoids compare1, but its ordinary waveform initialization
also writes ARR+1; that waveform configuration is outside this slice.

The following edge rules are explicit functional policies. They have source
usage evidence, but are not silicon timing measurements:

* The counter starts at zero and increments on divided input edges. An
  ordinary nonzero compare latches when the increment reaches its value;
  overflow clears the counter to zero and latches update status. ARR=0 has
  a one-tick period. Disabling a counter preserves its count and prescaler.
  Lowering an immediate ARR below the current count does not clamp it; the
  count wraps through 32 bits before reaching the new update point.
* Without ARPE/OCPE, ARR/CCR writes update their shadow values immediately.
  With preload enabled, the next overflow or software update transfers the
  pending values. While running, every accepted pending/immediate change
  must remain inside the supported compare range; contradictory changes
  are rejected without modifying the valid configuration. Stop the counter
  before changing prescaler or preload policy. A combined policy-change and
  enable write validates the effective post-write shadow pair, including
  mixed ARPE/OCPE selections, before committing any control/shadow changes.
* Software UG completes on one live input-clock edge, clears count and
  prescale, and transfers preloads. A stopped clock holds this pending
  request; reset cancels it. URS excludes the software update from update
  IRQ generation, while overflow still generates it. The pending strobe
  readback and one-edge synchronization are model policies.
* Input-clock changes preserve whole prescaler cycles and discard fractional
  input phase. MMIO and local IRQ delivery stay accessible with the clock
  stopped. Mask/unmask and W1C do not reset counters or prescaler phase.
  Large virtual-time jumps coalesce periodic events into their latched
  status; the model does not schedule one host callback per elapsed period.
* Global reset and whole-system reset cancel updates, clear counters,
  preloads and IRQ state. This does not implement deep-sleep retention.

Waveform/pad output, polarity, complementary/deadtime modes, down/center
counting, capture, triggers, repetition counters and independent-counter
extensions are not implemented. Nonzero settings for these modes return a
bus error under the strict unsupported-access policy; this is not a claim
that silicon faults those valid hardware configurations. In particular, no
unverified PWM level is connected to a board LED or GPIO pad.

There are important source gaps behind this boundary. The manufacturer's
V2.1 datasheet section4.26 specifies four independent counters per PWM group
(one simple independent PWM1 and paired PWM2/3 and PWM4/5). The selected SDK
structure ends at the three-counter legacy block, while its generated macro
header extends to TIM4/5/6. Neither header alone proves six independent
counters exist on BK7258. The same core structure/LL/HAL are still present
in the manufacturer's official SDK at
``4ca389311a7ef641f10b94d298dc07ee16b0f79c``. Generic API waveform diagrams
and comments inherited from another IP version do not resolve this conflict.
CHxP is described as input polarity in generated fields but used as output
initial level by the HAL; exact pad-pair inversion and compare0/ARR+1 edges
remain unresolved. These modes stay blocked pending a revision-specific
register description or corroborating hardware trace.

Native qtests cover both units and all six legacy counter registers,
individual compares, three-core routes, masking/W1C, independent prescalers,
gates/source loss, preload transfer, URS, reset during a pending update,
32-bit wrap, coalescing and rejected modes. Native Cortex-M33 probes enter
actual IRQ5/43 handlers; a missing PWM1 SYS route must fail with completion
status present. Unsupported pad-output writes must produce a precise
BusFault at their actual address. Mixed-preload enable regressions also
require atomic rejection: the pending pair, previous shadows and disabled
counter must remain unchanged when the prospective shadow pair is invalid.
These tests establish counter/IRQ paths,
not working PWM waveforms, pad routing or complete PWM support.

DMA shared-RAM functional boundaries
------------------------------------

There are two eight-channel controllers at ``0x45020000`` and
``0x45030000``, with their usual nonsecure MMIO aliases. The initial slice
implements only aligned, nonsecure/unprivileged, single-block transfers with
equal source/destination widths of 8, 16 or 32 bits. Source and destination
increment independently, or hold a fixed address. The 16-bit length field is
byte-count minus one; the 17-bit remaining field can represent 65536 bytes.
Request selector zero is the SDK's ``DMA_DEV_DTCM``/memory mode, also used by
its general memory-copy routine. That name does not establish which private
core TCM a DMA bus master can access.

Each controller has its own QEMU ``AddressSpace`` linked to a SoC-owned
RAM-only container. It contains the four aliases of the shared 640-KiB SRAM,
not a CPU's private address space. Real ``dma_memory_read/write`` transactions
carry nonsecure, unprivileged normal-memory attributes. Internal requester
IDs ``0x100 + 8 * unit + channel`` distinguish these masters from CPUs; these
are model tags, not claimed physical AHB HMASTER IDs. This slice neither
implements MPC/PPC/PRRO nor checks a full chip security policy. Mapping both
address aliases does not establish TrustZone conformance.

Private TCM, Flash/XIP, PSRAM and peripherals are deliberately absent from
that DMA view until their bus contracts are established. An access to them,
or beyond SRAM, produces a real failed memory transaction. The channel stops,
sets BUS_ERROR, preserves the remaining length/current addresses, and does
not set FINISH for the failed block. Already committed earlier beats remain
visible; the model does not roll back a partial copy or fabricate completion.
This bounded-view rejection is a model boundary, not evidence that all those
addresses are inaccessible to physical BK7258 DMA.

Register facts and bounded policies are separated as follows:

* Global ``+0x08`` bit0 releases reset; bit1 bypass is readback-only here.
  Channels start at ``+0x40`` with stride ``0x40``. The selected mode exposes
  source/destination start/current addresses, remaining bytes, FINISH/HALF/
  BUS_ERROR status and their local masks. Status bits18/19/20 are W1C, as
  used by the SDK's separate clear operations. Zero does not acknowledge.
* The NS enabled-pending summary at ``+0x1c`` routes to physical IRQ0 for
  DMA0 and IRQ57 for DMA1, then through the existing per-core SYS masks.
  Secure channel attributes, privileged channel attributes and non-default
  interrupt allocation are rejected rather than accepted without effect.
  Secure IRQ11/56 and multiple interrupt-allocation modes are not supported.
  The summary's enabled-pending interpretation is the chosen routing policy;
  exact silicon raw-summary/readback behavior remains to be established.
* Equal-priority channels receive one beat each in round-robin order. One
  beat performs its actual read followed by its write. HALF latches after
  at least half of the block's bytes commit; one-byte blocks latch HALF and
  FINISH together. Exact half-edge, arbitration, buffering and completion
  timing are functional policies, not bus-analyzer measurements.
* Event counters expose only zero/one unacknowledged event. Rearming while
  any event remains pending is rejected. Repeat/loop mode, multiple pending
  event counting, unequal widths, burst/pixel modes, nonzero priority,
  pause/flush controls and peripheral request selectors are unsupported.
  These restrictions avoid guessing hardware wrap/count/rearm semantics.
* The HCLK input is wired to the existing fixed 26-MHz diagnostic clock.
  A beat takes two source cycles, rounded up to virtual nanoseconds. This is
  a functional read/write scheduling policy, not a measured DMA/core ratio
  or bandwidth. Mask/W1C writes do not restart its deadline. Pending phases
  can pause/resume on a clock input change, but the chip's dynamic HCLK mux,
  gates and retention domains remain unimplemented. SYS memory-shutdown
  bits must not be misrepresented as clock gates.
* Channel disable cancels an undelivered beat and preserves progress.
  Controller/global or whole-system reset cancels all pending beats, clears
  channel state and IRQs, and retains already committed SRAM bytes. Active
  transfer configuration changes other than interrupt masks/W1C/disable are
  rejected. Unsupported MMIO/configurations return a bus error as a strict
  diagnostic policy, not a claim about silicon's handling of those writes.

Native qtests exercise all sixteen channels, all three widths, all four
increment combinations and all SRAM aliases; half/completion mask/W1C and
three-core IRQ routes; partial errors, inaccessible addresses, no peripheral
side effects, round-robin progress, disable/reset cancellation, maximum
65536-byte blocks and bounded event rearm. Native Cortex-M33 probes verify
actual DMA0/1 interrupt entry and shared-memory data, source/destination
boundary failures and private-TCM isolation. A missing DMA1 SYS route must
fail despite successful data transfer; unsupported secure-mode configuration
must produce a precise BusFault with the correct address. These tests do not
establish peripheral DMA handshakes or full interconnect/security behavior.

Peripheral request wiring is explicitly blocked pending the corresponding
port contract. For example the SDK's UART RX DMA setup aligns the FIFO
address back to a word while selecting an 8-bit transfer and UART_RX request;
the ordinary CPU RX accessor instead uses the byte lane at FIFO+1. That is
insufficient evidence to invent a generic ready signal or widen CPU MMIO.
The configured RX8-to-RAM32 and RAM32-to-TX8 paths additionally require width
conversion. The DMA API documents one to three residual bytes and the UART
RX service explicitly flushes the source buffer before stopping/accounting.
Request selectors (UART0 TX/RX=1/2, UART1=3/4, UART2=5/6) are established, but
request assertion/acknowledgement, partial destination byte strobes, remaining
count commit points, and cancel/clock-loss treatment of buffered data are not.
IRQ thresholds cannot be assumed to define DMA request eligibility. These are
open hardware contracts, not missing always-ready stubs to be filled in.

PSRAM and DPLL evidence boundary
-------------------------------

PSRAM remains absent. The SDK maps its controller at secure 0x46080000 and
nonsecure 0x56080000. The 0x60000000/0x70000000 views each describe a 64-MiB
address aperture, not the fitted memory capacity. The manufacturer lists
package options with 4, 8 and 16 MB SiP PSRAM. QSPI0 and QSPI1 use separate
apertures; an ordinary RAM mapping does not implement this controller.

The pinned CP HAL writes command 1/2/4 for mode-register write/read/reset at
controller +0x20, supplies address/data at +0x24/+0x28, and reads data at +0x2c.
Polling request bits until clear establishes a programming sequence, not a
command duration, a reset default or success for an absent part. The LL also
defines the software-reset bit, mode word, wrap field and write-through range
registers. Their presence does not resolve the remaining mode/timing meaning,
complete data packing or write-through/cache behavior. AP-side initialization
returns failure; the CP
path owns setup. Some CP fallback paths report success without checking the
returned part value, so an SDK success return cannot be our acceptance test.

The SDK's initial AP Memory values 0x8d09/0x8d08 are not immutable JEDEC IDs.
The first read contains writable configuration alongside vendor information.
For an explicitly selected APS6408L-OBMx, the current official
`AP Memory revision 3.9 datasheet
<https://www.apmemory.com/cn/downloadFiles/0324112221jz592656>`_
(2023-06-27), pages 15--17, defines stateful mode registers. Figure 12 pairs
addresses 0/1/2/3/4/8 with MR0+MR1, MR1+MR2, MR2+MR3, MR3+MR4,
MR4+MR8 and MR8+MR0 respectively, repeating the two returned bytes. Figure 13
writes one selected mode-register byte. MR0/4/8 are writable, MR1/2/3 are
read-only, and density is separately encoded in MR2. Power-up requires at
least 150 microseconds followed by the specified reset sequence; reset does
not guarantee array retention. These part facts do not establish the Beken
controller's upper response bits or serialization. A future fixture must
select a coherent part/revision and capacity, not independent arbitrary
identity and size values. It must remain possible to attach no part.

The inspected AP Memory PDF has SHA-256
``bfaf2b56bc13aead917fac0a21adf6796bf9911cb043099bbdf1ee26569ec1e4``.
The current register diagrams were visually checked; the PDF itself is not
redistributed in this source tree.

DPLL is a prerequisite to integrated PSRAM clocks. BK7258 datasheet section
4.3 identifies nominal CLK_320M and CLK_480M outputs; SYS ANA5 (+0x114) bit5
controls DPLL enable. The optional core-clock experiment below supplies
ideal nominal sources for its finite tuples; integrated PSRAM clocks and a
general PLL model remain absent. AON R7D (+0x1f4)
bit22 is raw DPLL_UNLOCK, while the separate bit21 refers to 26MPLL_UNLOCK.
SYS high-bank bit19 routes DPLL unlock as global IRQ51. Their placement does
not establish their reset values, settling, loss-of-lock or clearing behavior.
Do not synthesize lock or calibration success from an enable write.

The BK7258 calibration function toggles ANA0 SPITRIG/SPIDETEN and waits in
software; it returns success without polling lock. Its general DPLL-reset
function is a no-op. Shared HAL comments are not a reliable replacement for
this chip's register map: generic ANA11 DPLL descriptions name an actual
BK7258 buck register, and generic ANA0 N-divider-reset text conflicts with
this chip's open-loop field. Analog-register transfer completion is distinct
from PLL locking. No hardware POR values or arbitrary frequency-coefficient
equation have been established.

SYS+0x24 bits5/4 select the PSRAM source/divider and SYS+0x30 bit19 gates it.
The CP HAL programs four operating points: 480/0 for 240 MHz, 320/0 for
160 MHz, 480/1 for 120 MHz, and 320/1 for 80 MHz. These labels imply
``F / (2 * (1 + N))``, but the shared header and inline comments give
conflicting formulas. No inspected source proves an internal-versus-pin
clock explanation. A selected nominal rate must not silently become a
verified PSRAM timing contract or a three-board default.

The SDK also establishes finite digital-clock configurations without
specifying complete PLL locking dynamics. CP
``sys_hal_switch_cpu_bus_freq*`` programs SYS+0x20's core
mux[5:4]/divider[3:0] and each core control word's speed bit4. Its non-DCO
configurations give CPU0/1/2 respectively 240/480/480 MHz for a ``480M`` request,
160/320/320 for ``320M``, and equal 240, 120, 80, 60 or 26 MHz for the other
listed requests. The request enum is therefore not every core's frequency.
See the `CP frequency table and executable configuration
<https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/hal/sys_hal.c#L571-L636>`_.
The optional DCO path is a separate configuration, and bus-divider behavior
outside these exercised tuples is not established. The optional core-clock
model below implements these finite configurations.

For audio PLL, SYS ANA5 bit13 is active-high power-down; ANA25/+0x164 and
ANA26/+0x168 carry control and coefficient fields. The
`I2S driver
<https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/driver/i2s/i2s_driver.c#L859-L942>`_
associates two explicit configurations with 98.304 and 90.3168 MHz. This
supports future bounded configuration matching, not arbitrary coefficient
equations or lock/stabilization timing. SPI calls the first rate 98,000,000
in its baud calculation, while UART's ``APLL``-named selection is calculated
at 120,000,000. Those names must not be used to join all peripheral inputs
onto a guessed common audio-clock net.

The next bounded component can be an explicitly selected, stateful AP Memory
part and a separately clock-fed controller fixture. Integrated command and
array access still require evidenced source availability, divider stages,
MMIO-to-device packing and cancellation behavior. Required negative tests
include no part, no clock, read-only/reserved mode registers, interrupted
commands and fitted-capacity boundaries. Write-through/cache, x16 conversion,
Winbond mode, DMA, security and low-power retention stay separate gaps.

These observations use the already pinned SDK's
``cp/include/soc/bk7258/reg_base.h``,
``cp/middleware/soc/bk7258/hal/psram_ll_macro_def.h``,
``cp/middleware/soc/common/hal/psram_hal.c``,
``cp/middleware/driver/psram/psram_driver.c``,
BK7258 ``sys_reg.h``, ``aon_pmu_reg.h``, ``icu_map.h`` and ``hal/sys_hal.c``.
They do not add PSRAM support or establish a board BOM.

Experimental digital core clocks
--------------------------------

The default model retains its fixed 26-MHz core timing inputs. Enable this
bounded chip experiment explicitly, without selecting a firmware profile::

  -global bk7258-soc.experimental-core-clocks=on

Each emulated core then has an independent timing input connected to its
ARMv7M instance and both Secure/Nonsecure SysTick devices. This does not
scale TCG instruction execution, emulate cache performance, change the CPU
variant or prove analog DVFS behavior. An unavailable input pauses SysTick;
it does not halt the emulated instruction stream or prevent an independently
clocked peripheral interrupt from executing.
Existing core halt/power control and the incomplete power-domain contract
remain separate; these rates do not prove physical post-gate clock activity.

     - 60 / 60 / 60
     - 60

The speed bit is bit4 in each core's SYS+0x10/+0x14/+0x18 control word.
SYS+0x20 contains the core divider[3:0], mux[5:4] and bus divider bit6;
only bit6=0 is covered by the SDK's actual programming sequences. Its
validated bus-divider parameter is not written by that HAL. DCO and other
divider/speed combinations are not inferred from the endpoint examples.

The existing diagnostic reset tuple (low seven bits zero, all speed bits
zero) remains a separate 26/26/26-MHz boot exception. It preserves the
established reset contract and does not claim those speed bits' silicon
power-on interpretation. Every other unlisted tuple produces zero core and
nominal bus clocks and an explicit unimplemented diagnostic. The SDK changes
several fields sequentially; intermediate states outside the table remain
unsupported rather than silently retaining a previous rate. Each digital
write is applied immediately and a subsequent supported state recovers.

DPLL-backed tuples additionally require ANA5/+0x114 bit5 set in the
committed analog register. The existing one-microsecond register-transfer
operation controls when that enable write becomes visible; it is not a
PLL settling delay. The optional model supplies ideal nominal 320/480-MHz
sources, without inventing lock/unlock, calibration success, IRQ51 or
voltage behavior. A known tuple with the source disabled has zero clocks,
not an unsupported-configuration warning. Repeated writes that leave clock
periods unchanged do not restart consumers' timers.

``coreclk0``/``coreclk1``/``coreclk2`` expose the core inputs and ``busclk``
the table's nominal bus rate. No DMA or peripheral is connected to that bus
output: the SDK table does not establish their wiring. The existing
``cpuclk`` object remains the fixed diagnostic source for the RAM-only DMA
scheduler. UART, timer-group, PWM and external SysTick reference inputs keep
their independent XTAL/LPO sources; changing core fields alone must not
restart pending peripheral work. Changing a peripheral selector in the same
SYS word still invokes that peripheral's existing clock-change contract.

SysTick uses QEMU's native clock/ptimer propagation. A stopped input saves
the remaining whole count and recovery resumes it; fractional source phase
and physical mux glitches are not established. Tests distinguish remaining
count preservation from timer restart and stale-deadline behavior. Native
qtests exercise exact boundaries and actual guests exercise three-core
SysTick exception entry against RTC/TIMG deadlines, including missing-option
and missing-source failures. These remain chip functional probes, not STAR
identity, production AP SMP or complete firmware acceptance.

SPI master functional boundaries
-------------------------------

Two ``bk7258-spi`` controllers expose native SSI buses ``spi0`` and ``spi1``
at 0x44870000/0x45880000, with +0x10000000 aliases and IRQ7/17. SYS+0x30
bits 1/9 gate their inputs. SYS+0x28 bits 4/5 select XTAL (0) or the absent
APLL (1); selecting APLL logs that omission and stops the clock. Neither
controller chooses or constructs an external peripheral. Test invocations
explicitly attach QEMU's existing ``w25q32`` model, for example
``-device w25q32,bus=spi0,cs=0``. Its JEDEC EF4016 response is produced by
that upstream device model, not hardcoded in the BK7258 controller and not
claimed as a board BOM.

The supported slice is finite eight-bit, MSB/LSB-first, four-wire master
transfers: TX alone, or TX plus equal-length full-duplex RX. Both FIFOs hold
64 bytes. Channel enable, 12-bit word counts, source masks, FIFO-clear strobes
and W1C flags follow the SDK register layout. Data moves through ``ssi_transfer``;
there is no firmware identity detection or synthetic command response.
Missing SSI endpoints yield the core SSI API's zero-valued undriven input.
SPI has no address ACK, so the controller still finishes its clocks; the
source-built identification probe must reject the resulting wrong device ID.
This is a logical input policy, not an analog floating-MISO voltage model.

CTRL bit19 selects LSB-first in the vendor register layout and HAL. Native
SSI carries a value, with no width/order negotiation. For this eight-bit slice,
LSB transfers reverse the TX byte before the single SSI call and reverse its
returned byte. This is an explicit adapter convention for canonical MSB-oriented
byte-protocol endpoints, validated with the existing ``w25q32`` fixture. It is
not a claim that every arbitrary-width SSI peripheral follows this convention,
or that a separately configurable LSB slave and physical edge timing are modeled.
The vendor FIFO value remains in its programmed order; bit reversal changes
neither capacity nor word deadlines. Active bit-order changes are rejected
under the existing live-format policy.

The native fixture receives JEDEC command 0x9f from LSB FIFO byte 0xf9 and
returns EF/40/16 as FIFO values F7/02/68. Tests switch back to MSB between
frames and also use reversed WREN/RDSR/WRDI to observe the actual endpoint's
write-enable state. A gated word preserves its remaining source cycles; its
absolute deadline moves on recovery. Controller reset before completion must
leave the endpoint's write-enable state unchanged. Three source-built positive
cases execute both SPI IRQs in LSB mode. Three negatives require an intentionally
missing SPI1 route to fail despite completed peripheral transactions.

Sixteen-bit width is separately encoded and the LL divides byte lengths by two,
but its FIFO capacity/threshold units, CPU-access packing and inter-octet versus
inter-word spacing remain unresolved. Passing a sixteen-bit value directly to
``m25p80_transfer8()`` would consume only one byte and lose the upper bits.
Neither that shortcut nor an unproven two-callback timing split is modeled.

The SSI bus subtype accepts one CS0 endpoint with standard active-low CS or
no CS. Nonzero/duplicate chip selects and active-high endpoints are rejected,
rather than ORing multiple unintended responses. The controller exports a
``cs`` GPIO output and connects a standard attached CS0 input at reset/frame
start. This represents a direct logical bus attachment. Physical GPIO
alternate functions, external CS gates/inverters and board-specific routing
remain absent and must be modeled before claiming those board connections.
A peripheral lacking the promised standard CS input is rejected on use.

Clock/timing and error boundaries are deliberately explicit:

* The selected BK7258 AP configuration enables SYSTEM_CTRL; its HAL programs
  nonzero raw clock divisors from ``source / (2 * baud)``. The 13-MHz SPI-flash
  example therefore uses raw divisor 1 with the 26-MHz source. Raw divisor 0
  is rejected because its hardware meaning is not established; the unrelated
  older HAL branch using ``source / baud - 1`` is not used here.
* A modeled word takes ``(8 + byte_interval) * 2 * divider`` input cycles.
  The extra interval is a named functional spacing policy, not a measured
  interpretation of every encoding. The LL's configured interval 1 and
  RX sample-edge setting are retained. CPOL/CPHA/sample-edge fields have
  readback only: packet-level SSI does not validate SCK/MOSI/MISO edge timing
  or polarity mismatch. Tests use mode 0, not physical waveform assertions.
* CS asserts for a finite frame and releases at completion, channel stop,
  controller disable or reset. Gating pauses the pending word and preserves
  CS. Remaining source cycles round upward on a source change; sub-cycle
  phase is not preserved. Interrupt-mask/W1C/bypass-readback writes must not
  restart a pending deadline. Live divider/format/count changes are rejected.
  Channel-enable bits retain their programmed value on completion; software
  must clear them before arming a new frame and acknowledge old W1C status.
* TX service is a level below the selected 1/16/32/48 threshold while the TX
  channel is enabled; RX service is at or above the corresponding threshold.
  Status remains latched under masking and reasserts on W1C while its level
  condition persists. These level/reassertion details are functional policies
  beyond the source-proven threshold encodings.
* Initial empty TX waits for data without claiming completion. Starvation
  after the first word latches underflow and pauses until refilled. RX overflow
  latches an error and drops the newest word, preserving already queued data.
  These explicit policies are not measured silicon overflow/underflow timing.
* Controller reset cancels an undelivered word, clears queues/configuration
  and releases CS. TX FIFO clear also cancels its pending word. Bytes already
  delivered to a peripheral cannot be undone; that device may itself act on
  CS release. Whole-machine QEMU reset also invokes attached devices' own
  reset handlers and does not establish silicon reset-domain retention.
* Slave, 16-bit, three-wire, RX-only and unequal-length full-duplex
  modes, zero-length frame encodings, DMA and slave-release IRQ are outside
  this slice. Unsupported configurations, unknown registers, full TX writes
  and empty RX reads return transaction errors. As with UART/I2C, these are
  strict-model diagnostics, not claims about silicon BusFault responses.
  Validation also applies after a completed frame retains its enable bits:
  invalid writes leave configuration, queued bytes and slave state intact.
  A valid interrupt-mask update does not start another frame; software must
  still disable and re-enable the channel to transmit the queued next frame.

Native qtests cover both buses, real peripheral ID/write-enable state,
CS-separated command frames, all threshold encodings, FIFO integrity,
starvation/recovery, drop-new overflow, masks/W1C, three-core routes,
clock loss/recovery, unchanged deadlines on mask writes, canceled commands
and invalid chip-select wiring. Source-built probes execute IRQ7/17 and
must distinguish a missing SPI1 route from an absent endpoint; an unrelated
early failure cannot satisfy either negative. Separate precise-fault probes
cover the model's empty-read error policy.
Post-completion probes also require a precise fault at the nonsecure CFG alias
after a verified real-slave ID transaction, with the previous configuration
and completion state preserved. An unrelated early fault cannot pass them.

I2C master functional boundaries
-------------------------------

Two ``bk7258-i2c`` controllers expose native QEMU I2C buses ``i2c0`` and
``i2c1``. Their secure bases are 0x45850000/0x45860000, aliases add
0x10000000, SYS+0x30 gate bits are 0/8 and IRQs are 6/14. The board models
leave both buses empty. Tests explicitly add ``at24c-eeprom`` devices with
``-device at24c-eeprom,bus=i2c0,address=0x50,rom-size=256`` and its bus1
equivalent. These are replaceable external test fixtures, not claimed board
components. No board or OS-specific slave identity is built into the SoC.

The implemented register slice is GLOBAL +0x08, CFG +0x10, STATUS +0x14,
FIFO DATA +0x18 and EXTRA +0x1c. It supports the SDK's seven-bit master
sequence: enqueue the address byte before START; wait for the actual bus
address response; service FIFO state by atomically writing ACK/START/STOP
and clearing SM_INT. Bit0 is **write-zero-clear**, not W1C. A write-one
preserves an existing interrupt and cannot create one. ACK from an address
or transmitted byte comes from the attached slave API; absent devices give
NAK. While an event remains unserviced, software cannot overwrite its
latched response; servicing an absent-slave result cannot create ACK either.
This conservative write policy exposes errors and is not a claim about
undocumented silicon writes to a pending response bit.

Both FIFOs hold 16 bytes. TX service thresholds are modeled at 0/4/8/12
bytes remaining for INT_MODE 0/1/2/3; RX thresholds are 12/8/4/1 bytes.
The latter levels and the driver's corresponding writable-space values
come from the LL/HAL. Threshold service can leave data queued: IRQ is not an
unconditional end-of-transaction success. Same-address repeated START can
change direction without STOP. Clearing ACK after receiving sends NAK;
STOP ends the bus transaction and self-clears without a second completion
interrupt in this functional policy.

The SDK selects CFG.CLK_SRC=3 while computing the divider from XTAL.
That selection uses the SoC's gated 26-MHz input. Other encodings supply no
clock and log the missing source. The HAL's divider expression gives
``3 * (divider + 1) + 6`` input clocks per SCL period. This model schedules
nine such periods for each address/data byte and one for STOP, rounded up
to host virtual nanoseconds. This is functional latency, not measured wire
or setup/hold timing. Clock gating preserves remaining source cycles rounded
upward; fractional phase is not modeled. Changing the divider/source during
an active byte is rejected rather than guessing its physical behavior.
Rewriting unchanged configuration or changing the GLOBAL bypass/readback bit
does not gate a clock and must preserve the pending absolute deadline. Native
qtests check the exact boundary after repeated subcycle writes; an additional
source-built probe uses deterministic instruction timing to detect starvation
from such writes, then runs the ordinary bus/IRQ/repeated-START sequence.

The following boundaries remain explicit:

* The generic QEMU I2C API does not rescan an already selected bus for a new
  address during repeated START. A different-address repeated START is
  rejected without redirecting the transfer or pretending the old slave
  acknowledged the new address. Same-address direction changes are tested.
  An already externally owned bus rejects a new request; contention that
  appears during the functional delay logs an unsupported case and leaves
  the operation without automatic completion until software recovers. No arbitration-loss IRQ or
  external-master conformance is claimed, and reset does not end a bus
  transaction owned by someone else.
* Slave mode, ten-bit/general-call addressing, multi-master arbitration,
  analog SDA/SCL, clock stretching, timeout/idle detection and pinmux gating
  are absent. Their configuration fields do not fabricate status/completion.
  EXTRA output-control bits retain their setting; nonzero byte-interval
  settings are unsupported. No physical pad-waveform claim is made.
* Empty RX reads, full TX writes, contradictory START/STOP, unsupported
  register accesses and the unsupported repeated-address case return a
  transaction error without consuming/corrupting FIFO data. These deliberate
  strict-model policies are not claims that silicon raises BusFault for
  those software mistakes or for its valid device-ID registers.
* GLOBAL bit0 acts as synchronous reset release. Reset assertion or clearing
  CFG.EN cancels a pending byte, clears controller queues/status and releases
  the bus. Bytes already delivered to a slave remain delivered; reset cannot
  roll back an external device. Chip cold reset covers both controllers.
  Distinct power/reset-domain retention is not yet established.

Native qtests exercise both buses, all four FIFO service modes, overflow
rejection/readback integrity, W0C, ACK/NAK and three-core route masks,
repeated START, clock pause/recovery and reset before an external write.
Source-built guest tests perform real IRQ6/14 entry and EEPROM readback on
each machine. Their missing-route negative requires observing a completed
controller transaction with the specific absent SYS route, rather than
accepting an unrelated early failure. Empty-read fault probes separately
validate the strict-model access boundary.

General timer functional boundaries
-----------------------------------

Two independent ``bk7258-timer`` devices each contain three 32-bit up counters
and one 4-bit common prescaler (divide by 1..16). Group0 is at 0x44810000,
group1 at 0x45800000, with +0x10000000 aliases and shared group IRQ3/13.
SYS+0x30 bits 4/13 gate them independently. SYS+0x20 bits 20/21 select
CLK32 (0) or XTAL (1). CLK32 is connected to the selected AON LPO as an
explicit topology assumption: the SDK establishes the selector names but
not the complete internal clock netlist. XTAL is the existing 26-MHz source.

The SDK names CTRL bits 7..9 ``timer*_int_en``, but its active status getter
and write-one-clear loop use them as interrupt status. Accordingly, this
model makes them latched W1C, ORed into the group IRQ; it does not fabricate
an additional local interrupt mask. The existing per-core SYS and NVIC masks
control delivery. CTRL bits 0..2 enable channels and bits 3..6 select the
prescaler. Words +0x10/+0x14/+0x18 are channel end values, not live counts.
READ_CTRL +0x20 has channel bits 2..3 and request bit0; the completed result
is at +0x24. Hardware IDs/version/device-status remain unimplemented and
return transaction errors rather than invented fixed values.

The following are bounded, testable functional policies, not measured silicon
edge conformance:

* On reaching a nonzero end value the counter returns to zero and latches
  status. End zero denotes a complete 2^32-edge cycle. Lowering a live end
  below the current count waits through natural 32-bit wrap; it does not
  clamp or synthesize completion. This preserves the failure mode described
  by the driver's stop-before-changing-period workaround, without imitating
  its physical asynchronous-disable delay.
* Disabling a channel clears its count, but not latched status. A status-only
  acknowledgment with unchanged enables/divider preserves counter phase.
  The common prescaler continues while the group clock is live; changing
  its divisor clears its partial prescaler count.
* Snapshot completes on the next live input-clock edge, after any coincident
  counter increment. It can read disabled channels. A stopped source leaves
  the request pending. Rewriting a busy request or selecting channel 3
  returns an error and preserves the pending operation; writing zero to the
  result clears only the read latch. The source proves a hardware-cleared
  request but does not specify the one-edge latency chosen here.
* GLOBAL +0x08 bit0 is treated as reset release. Writing it clear cancels
  pending work and clears counters/configuration/status; bit1 retains the
  clock-bypass setting but cannot generate an absent source. Reset assertion
  is synchronous in this model. Register accesses and latched IRQ status
  remain available while the functional source is gated.
* Clock interruption retains whole input clocks, prescaler progress and
  counters. Fractional source-clock phase is discarded on source changes.
  Elapsed periods coalesce while status is already pending; this prevents
  host callback storms without dropping the counter's modulo progress.
* QEMU system reset clears both groups. Separate AON/digital power-domain
  retention, deep-sleep wake routing and vendor identity are not established.

Native qtests cover both groups/all channels, all 16 divisors at deadline
boundaries, W1C and three-core routes, live end changes, 32-bit wrap, absent
sources, stalled/busy/invalid snapshots and reset cancellation. Bare-metal
functional probes exercise actual IRQ3/13 exception entry and a missing-route
negative, plus a genuine BusFault on invalid channel selection. No OS or
production firmware source is changed for these tests.

RTC functional boundaries
-------------------------

The known register contract comes from the SDK's 64-bit RTC structure/HAL:
control at +0x00; upper low/high at +0x04/+0x18; tick low/high at +0x08/+0x1c;
counter low/high at +0x0c/+0x28; synchronized upper at +0x10/+0x20 and tick at
+0x14/+0x24. Control bits 0/1 hold reset/pause, bits 2/3 enable upper/tick IRQ,
bits 4/5 are W1C status and bit 6 enables the RTC core clock. Counter halves
are live reads, not a fabricated atomic snapshot; the SDK retries split reads.

The following are explicitly bounded functional policies, not measurements of
the silicon's edge ordering or CDC circuitry:

* Upper is inclusive: the counter visits ``upper`` and wraps to zero on the
  following LPO edge. Equality reached by counting latches the corresponding
  status independently of its interrupt mask. An upper of zero keeps the count
  at zero and latches status on an edge, without an unbounded host timer loop.
  Lowering upper below the current counter does not clamp it; it continues
  through natural 64-bit wrap before reaching the lower threshold.
* Each 32-bit threshold half transfers after three enabled LPO edges. This
  implements the SDK's documented three-cycle synchronization hazard. A second
  write to the same half while pending is rejected and logged; other halves
  remain independent. Clock loss or clearing core-enable pauses transfers.
  Counter-stop/reset do not prevent threshold synchronization. A newly synced
  value equal to the current count does not invent an immediate compare edge.
* Control, W1C and software counter-reset actions are immediate at the MMIO
  interface; their physical synchronizer latency is not reproduced. Disabling
  the core preserves count/status and does not acknowledge a pending IRQ.
  Clock-source changes retain whole ticks but discard fractional tick phase.
* QEMU's current whole-system reset path is treated as a cold RTC reset: it
  clears count, thresholds, status and pending transfers. This supports the
  current full-reset diagnostic, not digital-only/deep-sleep retention. The
  SDK explicitly observes a running RTC across some reboot/sleep paths; those
  reset domains are still absent and must be implemented before claiming that
  behavior. No fixed reset-cause or successful wakeup register is supplied.

Arithmetic retains 64-bit thresholds and low-word carry without truncating to
32 bits. Timers coalesce elapsed clock edges, preserve masked status, and do
not wrap deadlines beyond QEMU's representable virtual time. Native qtests
cover two-word thresholds, inclusive wrap, lower-threshold/zero policies,
delayed readback, busy writes, missing source, stop/resume, W1C, per-core SYS
routing and cold-reset cancellation. These tests validate the stated model
contract; they are not evidence that the unresolved edge policies match a
physical BK7258 revision.

MBOX0 functional boundaries
--------------------------

MBOX0 diagnostic policies for undocumented edge cases are explicit: channel
outputs combine the individual RX/error enables; disabling a channel masks
traffic/IRQ but retains queued messages. Enabled or nonempty FIFOs cannot move
or resize, and their partitions cannot overlap or exceed the eight slots.
Invalid partitions are rejected; empty/disabled SID reads return 0xf and log a
guest error without consuming data. Unauthorized TID/SID operations latch the
documented addressed-channel WRERR/RDERR; protected configuration/data writes
are unsupported bus errors because their exact silicon response is unknown.
A full destination preserves its old entries and latches sender WRFULL. An
unavailable destination is rejected with WRERR. Raw self-send is allowed; this
is not the higher-level SDK logical-channel policy. Reset clears queues and
IRQs. No physical interconnect latency or DMA-master identity is modeled; the
global qtest bus uses CPU0's view. The 0x100 aperture covers known registers,
not a measured silicon decode window.

Migration/snapshot state is unsupported and the SoC is marked unmigratable.
Unimplemented registers report through ``-d unimp`` instead of fabricating
successful device identification or completion bits.

Building and running
--------------------

On a Linux host with GCC, GLib development headers, Python, Meson and Ninja::

  mkdir ../qemu-build
  cd ../qemu-build
  ../qemu-bk7258/configure --target-list=arm-softmmu \
    --without-default-features --disable-docs --disable-user \
    --disable-tools --disable-rust --enable-tcg --enable-werror
  ninja qemu-system-arm
  ./qemu-system-arm -M help

The diagnostic entry bypasses ROM and bootloaders: CPU0's vector table is at
``0x02010000``. Use an ELF linked with a valid vector there. For the trusted
bare-metal fixture maintained in this QEMU repository::

  printf Z | ./qemu-system-arm -M t5_board -display none -monitor none \
    -serial stdio -kernel diagnostic.elf \
    -semihosting-config enable=on,target=native -d guest_errors,unimp

Semihosting is used solely to report fixture exit status. It can expose host
files to guests: do not enable it for untrusted images. Build the fixture
using the independent functional test below. The model uses standard QEMU
command-line and test interfaces; an OpenVela-specific CLI is not required.
Guest fixture C is never compiled into a host QEMU device.

A passing diagnostic proves CPU instruction execution, SRAM aliases,
SysTick exceptions, core release/stop/reset, private TCM, UART receive IRQ and
system reset within this slice, including a real watchdog NMI under PRIMASK.

Earlier external firmware validation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

A separate real NuttX ``aidk_ai_toy/native_nsh`` CP ELF reaches NSH through
unchanged NuttX/SDK startup, UART, NVIC and SysTick paths. Its existing-Kconfig
profile excludes optional product peripherals; it does not patch startup to
detect QEMU. The contest CLI ``qemu native-nsh --build-manifest ...`` checks
native task listing, UART commands, a background sleeper plus foreground
progress, elapsed uptime, error handling and guest reboot. It requires a
rehashed direct-build manifest and records ELF/source identity.

QEMU's optional FPB/DWT/debug-monitor registers are unimplemented. The pinned
NuttX ``arm_enable_dbgmonitor()`` probes them because ARCH_CORTEXM33 selects
ARCH_HAVE_DEBUG. The NSH harness preserves and counts exactly those eight
startup messages, rejecting every other unknown access, including DWT cycle
counter reads. No debugger, breakpoint or performance-counter claim follows.
The restricted native NSH also passes through physical NOR XIP without the
ELF loader. The unchanged direct product CP passes Flash initialization and
next faults at unimplemented RF register 0x4980c000 (SDK rc_drv_set_rf_en).
The MCUboot-configured CP reads unimplemented AON R7A reset-cause storage
0x440001e8 before Flash. Its snapshot/POR/reset-domain semantics are not
established by the pinned SDK, whose register definition is reserved. Its
``reset_reason.c`` writes software CP/AP reason tags into keyed R0 fields
and reads those fields back from R7A during startup; that software usage
alone does not define the hardware snapshot/clear timing across POR,
watchdog or deep-sleep resets. The missing reset-domain contract remains
blocked rather than synthesized from software reason enumerations. Both
probes enter CP directly: they do not execute ROM/BL1/BL2. Known-stop tests
retain exact configuration-specific missing-device boundaries; they do not
assert successful product boot.
Production CP/AP boot, AP SMP scheduling, RPMsg software traffic, firmware
updates and hardware timing remain outside this acceptance.

Physical NOR contract
---------------------

Without ``-kernel``, the board uses physical NOR mode. With no drive, the
array starts erased, retains changes across system reset and loses them when
QEMU exits. For process-restart persistence, use an operator-owned 8-MiB raw
simulation image with
``-drive if=pflash,unit=0,format=raw,file=nor.bin``. An optional second raw
512-byte sector at ``unit=1`` persists NV SR1/SR2/SR3 in its first three bytes;
the remaining bytes must be zero. Fresh delivery state is 00 00 20. Omitting
that status drive makes status process-local, not restart-persistent. Both
backends require exclusive write/resize ownership; the device flushes a
successful mutation before updating its cached array/status. Readonly backing
or host I/O failure stops the VM rather than claiming a completed write.
A failed host commit can have partially changed the host file; the NOR latches
that failure and rejects further array access, even after reset.

The entry vector remains 0x02010000, bypassing bootloaders. The contest CLI's
``qemu native-nsh --physical-nor`` builds a fresh simulation-only image from
validated finalized artifacts and layout offsets, leaves identity/calibration
areas erased, and refuses to overwrite existing NOR files. It does not create
a board-flashable production release or run a bootloader/OTA flow.

Controller operations complete after one microsecond of virtual time, solely
as an asynchronous functional boundary, not physical program/erase timing.
Reset before that deadline cancels the operation. NOR programming ANDs bits
and wraps within a 256-byte page; erases and BP/CMP protection follow the part
contract. Protected writes are no-ops. Malformed or unsupported asynchronous
operations stop the VM; unknown MMIO/command accesses fault. FIFO underflow,
overflow and writes during active transactions are rejected. XIP observes
the last committed array during a pending operation, an explicit functional
read-cache abstraction rather than SPI bus arbitration.

CRC16 uses polynomial 0x8005, initial 0xffff and big-endian trailers. Complete
erased FF frames may be read when ALL_FF_OK is enabled. Failed-read counts
saturate at 255; this counter policy is functional, not measured hardware.
Quad XIP requires QE. The direct-entry configuration enables CRC/ALL_FF_OK;
this is not a claim about silicon power-on state. Controller-managed WREN is
inferred from the SDK's no-op write-enable wrappers. Its op7 16-bit status
transaction is modeled as two separately enabled SR-byte writes; the exact
physical controller waveform is not known.

Unsupported: raw SPI framing, SFDP/UID/security/OTP, SRP1 special modes,
volatile-status enable, suspend/deep-powerdown, page-select modes, direct CPU
XIP writes, CRC-disabled mode, remap/encryption, flash performance, brownout

Independent hardware regression
-------------------------------

The downstream QEMU repository owns its model tests. They run without an
OpenVela checkout, its CLI, a firmware build, an Arm cross-compiler or a guest
image. From a clean QEMU checkout::

  mkdir build-bk7258 && cd build-bk7258
  ../configure --target-list=arm-softmmu --without-default-features \
    --disable-docs --disable-user --disable-tools --disable-rust \
    --enable-tcg --enable-werror --enable-tests
  ninja qemu-system-arm tests/qtest/bk7258-test tests/unit/test-bk7258-clock
  ./pyvenv/bin/meson test --no-rebuild --print-errorlogs test-bk7258-clock
  ./pyvenv/bin/meson test --no-rebuild --print-errorlogs qtest-arm/bk7258-test

The registered libqtest cases include physical NOR with and without a host
file, logical-kernel mode and rejected conflicting loading/geometry inputs.
They also cover SRAM/MMIO aliases, UART IRQ mask/W1C,
whole-system reset, watchdog keys/feed/stop/expiry, GPIO edge/level masking,
asynchronous analog cancellation, clock ratio/IRQ routing/source loss,
mailbox routing/order/full/protection/reset, and persistent NOR AND-program,
protection, erase, reset cancellation, CRC/XIP and read-only error handling.
Each hardware case runs on all three machine names. Board cases additionally
check the actual LED/key binding, wrong-pin isolation, output disable, active-low
key IRQ/W1C, held contact across reset, released contact/internal pulls and
read-only LED observation. These qtests do not execute guest CPU instructions.

These cases were adapted from the Apache-2.0 contest hardware tests at
``ffe8356bf8b0e4eeaa504b6bcfaaf529bc842b43``,
``tests/host/bk7258/test_bk7258_qemu.py``. The source attribution and license
are retained in ``tests/qtest/bk7258-test.c`` and its adjacent LICENSE file.
They are maintained here independently, not imported or executed from the
contest project. QEMU checkpatch currently rejects Apache-2.0 in its license
allowlist; this downstream adaptation preserves its actual source license
rather than relabeling it to make the lint result green.

OpenVela is an optional external firmware consumer and evidence source.
Earlier integration/firmware checks in that independent project do not serve
as this repository's core test runner. The qtest and bare-metal functional slices do not replace
earlier sanitizer or external firmware checks. Future boot tests
must identify their external firmware assets and hashes without changing the
consumer's product code or requiring its build workflow.

Independent CPU execution regression
------------------------------------

Install ``arm-none-eabi-gcc`` (or set ``BK7258_TEST_CC`` to a trusted compiler)
in addition to the host build dependencies, configure with ``--enable-tests``,
and run QEMU's registered functional test from the build directory::

  QEMU_TEST_KEEP_SCRATCH=1 ./pyvenv/bin/meson test --setup thorough \
    --print-errorlogs func-arm-bk7258

``--setup thorough`` is required: QEMU's default quick setup excludes these
cross-compiler-dependent tests. The standard runner installs its own declared
Python test dependencies. Without a compiler the test explicitly skips; this
repository's CI installs the compiler and runs the complete registered suite.
No OS checkout or firmware download is required.

The functional fixtures use the native runner's public
``QEMUMachine.set_qmp_monitor(False)`` API. They only need the console, process
exit and instruction logs, not a monitor transaction. ARM semihosting calls
``exit(ret)`` directly, so both initial QMP negotiation and a synchronous
``cont`` reply can race a tiny guest's exit. Disabling the unused monitor avoids
both races without suppressing exceptions, adding arbitrary guest delays or
relaxing exit/log assertions. Native qtests still use their normal QMP/qtest
connections. For local stress repetitions use
``--repeat 10 --num-processes 1``: concurrent repetitions share the standard
runner's per-test artifact directories and must not overwrite each other.

``tests/functional/arm/test_bk7258.py`` compiles the adjacent
``guest-src/bk7258/diagnostic.c`` and linker script, then executes positive and
negative inputs on all three boards using TCG. It checks guest UART markers
for SRAM aliases, a real NMI under PRIMASK, both SysTick sources, independent
TCM, secondary release/halt/reset, three-core mailbox IRQ/protection, UART RX
IRQ and whole-system reset. Every positive case repeats the hardware sequence
after reset; every bad-input case must reach the guest fault marker and exit
with status 1. Unknown MMIO logs, missing markers, unexpected exit status or
bounded wait expiry fail the test. This is trusted bare-metal code, not NuttX,
AP SMP scheduling or product boot acceptance.

The runner retains console/MMIO logs and compiler/source/ELF/emulator hashes.
``QEMU_TEST_KEEP_SCRATCH=1`` also keeps the generated ELF. These sources are
adapted from the Apache-2.0 contest fixture at
``ffe8356bf8b0e4eeaa504b6bcfaaf529bc842b43``,
``tests/host/bk7258/qemu/diagnostic.{c,ld}``. Their original license is retained
beside them. Formatting/comments and declaration placement were adapted to
this tree; the initial import produced a byte-identical ELF with local GCC
14.2. The fixture has since gained a source-loss check: CPU-clock SysTick
measures three milliseconds with DWDT armed but its LPO absent, then restoring
DIVD must deliver NMI under PRIMASK. The Python runner is a new
GPL-2.0-or-later downstream test.

Six additional cases build ``sys_fault.c`` for all three machines: an
unimplemented SYS identity read and an unsupported NS-alias status write must
reach the real Cortex-M33 HardFault handler with precise BusFault flags and
the matching BFAR. A silent read-zero or ignored write exits with failure.
These verify the model's strict unsupported-access policy, not silicon's
response to undocumented registers. Their MMIO logs must contain exactly the
expected unsupported operation; the six ordinary diagnostic cases still
require empty error logs.

Nine physical-XIP cases build the source-only
``guest-src/bk7258/xip_cross_page.{S,ld}`` fixtures, adapted from the same
Apache-2.0 contest revision. The linker places one Thumb-2 instruction at
``0x02010ffe``, crossing the 4-KiB MMIO boundary. A local polynomial-division
CRC encoder constructs an erased 8-MiB physical NOR image with 32+2 framing;
the runner does not import any OpenVela image helper and does not use
``-kernel``. For each board, a correct comparison must exit 0, an intentional
wrong comparison must exit 1, and corrupting the second-halfword frame must
reach the real guest HardFault handler and exit 2. Instruction logs must show
the expected executed address and CRC failure only in the corruption case.
The logs include source, ELF, raw payload and NOR hashes. This proves a small
physical-XIP fetch/error path, not reset-ROM or complete firmware boot.

Six RTC cases build ``rtc.c`` and test pause, missing LPO, restart and real
IRQ54 delivery on every board. Deliberately withholding the SYS interrupt
route must fail within the CPU-clock deadline; it must not receive a synthetic
success. These are chip-level probes, not an OS profile or application.

Eighteen UART access cases reuse the MMIO fault fixture, covering unknown
reads and read-only status writes for UART0/1/2 on every board. They require
the exact exception/status/address and fail against the earlier read-zero,
ignored-write model. Supported console operations retain their existing
strict output/exit checks. Native qtests additionally cover a 128-byte FIFO
boundary, a host-buffered extra byte, ring wrap, IRQ masking/W1C and reset.

Twenty-seven TX cases build ``uart_tx.c``: every UART on every board must
reach the genuine CPU0 IRQ4/15/16 handler for completion and service, verify
masked status, and retain byte order. Removing its SYS route must fail the
normal probe despite completed output. Filling the finite queue and writing
through the nonsecure alias must fault precisely with an unchanged full count.
UART1/2 use independent file chardevs whose contents are checked exactly.
The shared source-only console helper polls capacity and drains each byte
through a newly acknowledged TX_FINISH before exit/reset, keeping test output
independent of compiler inlining or stale completion latches. Its hash is
recorded alongside every C fixture; no external firmware is changed.

Nine timer-group cases build ``timer.c``. Each board must deliver real
IRQ3 and IRQ13 from independently selected CLK32 and divided XTAL sources,
pause a snapshot across clock gating, and cancel it on reset. Withholding the
group1 SYS route must fail within the independent CPU-clock deadline. An
invalid channel request must enter the genuine HardFault handler with
precise BusFault status and matching BFAR, rather than returning success.

Register provenance

SDK register inventory
~~~~~~~~~~~~~~~~~~~~~~

The SDK contains register-level definitions and executable programming
sequences; a separate register manual is not a prerequisite for every model
increment. At the user's SDK revision
``4ca389311a7ef641f10b94d298dc07ee16b0f79c``, the CP BK7258 ``soc`` directory
has 26 ``*_reg.h`` and 26 ``*_struct.h`` files, and its ``hal`` directory has
27 ``*_ll.h``, eight ``*_ll_macro_def.h`` and 17 ``*_ll.c`` files. These counts
describe that directory inventory, not complete hardware coverage. Common
HALs and drivers supply the initialization, polling and acknowledgement
sequences which must be checked against generated comments.

The following source index uses byte offsets. A generated ``REG_0xNN`` word
index is multiplied by four; it must not be used directly as a byte offset.

* `Address map
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/include/soc/bk7258/reg_base.h#L16-L80>`_:
  ``SOC_ADDR_OFFSET`` chooses the secure map or its +0x10000000 nonsecure
  view. SYS is 0x44010000, AON PMU 0x44000000, GPIO 0x44000400, PSRAM
  control 0x46080000 and UART0/1/2 0x44820000/0x45830000/0x45840000.
  Alias arithmetic alone does not define security enforcement.
* `UART fields
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/soc/uart_struct.h#L28-L136>`_:
  +0x08 global control, +0x10 TX/RX enable and frame/divider configuration,
  +0x14 FIFO thresholds, +0x18 counts/readiness, +0x1c TX[7:0]/RX[15:8],
  +0x20 IRQ enable and +0x24 status. The
  `LL acknowledgement code
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/hal/uart_ll.h#L363-L400>`_
  explicitly requires W1C rather than read-modify-write. The
  `HAL
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/common/hal/uart_hal.c#L24-L104>`_
  programs frame format, thresholds and ``source / baud - 1``, and flushes
  through directional enable toggles. These are sufficient for the existing
  bounded FIFO, character-width and timing model. Parity polarity is
  contradictory: ``uart_struct.h`` says 0=even/1=odd, while ``uart_reg.h``
  lines 33--34 and the LL conversion implement 0=odd/1=even. No physical
  parity waveform is implemented from either interpretation.
* `GPIO fields
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/soc/gpio_struct.h#L23-L133>`_:
  GPIO+4*n holds pin data, direction, pulls, alternate-function enable and
  interrupt controls; SYS+0xc0..0xd8 holds four-bit mux slots for 56 pins.
  The `mapping sequence
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/common/hal/gpio_hal.c#L183-L223>`_
  disables ordinary GPIO output/input/pulls before enabling alternate
  function. Therefore active-low ordinary GPIO output enable is not proof
  that a UART alternate-function output is disabled. The per-pin mux map is
  known; UART pad ownership under disable/reset/clock loss is still separate.
* `AON R0 software fields
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/soc/aon_pmu_struct.h#L25-L38>`_
  include CP reason[11:4], GPIO retention[19:12], reset count[23:20] and AP
  reason[30:24], although the generated ``aon_pmu_reg.h`` labels [30:2]
  reserved. The driver writes its two-key commit sequence to R25 (+0x94).
  `R7A/R7B accessors
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/soc/aon_pmu_ll.h#L733-L740>`_
  read +0x1e8/+0x1ec, and
  `reset_reason_init
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/driver/reset_reason/reset_reason.c#L185-L253>`_
  decodes R7A's CP/AP reason fields. The missing facts are capture, clearing
  and reset-domain retention, not the register's existence.
* `PSRAM LL
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/hal/psram_ll_macro_def.h#L43-L172>`_
  defines +0x08 software reset bit0, +0x10 mode/wrap[30:28], +0x14
  configuration, +0x20 command, +0x24 address, +0x28 write data, +0x2c read
  data and four range pairs at +0x40..0x5c. The
  `command HAL
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/common/hal/psram_hal.c#L28-L103>`_
  supplies write/read/reset commands 1/2/4 and polls the corresponding
  request bit. This establishes a real controller interface; the PSRAM/DPLL
  section above identifies exactly which packing/timing/device facts remain
  unresolved.
* `SYS core control
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/soc/bk7258/soc/sys_reg.h#L53-L167>`_
  includes status at +0x0c and per-core reset/power/mask/halt/speed/vector
  fields at +0x10/+0x14/+0x18. The
  `actual secondary start/stop path
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/components/bk_startup/system_main.c#L173-L225>`_
  passes 1 to start and 0 to stop; the
  `SYS power driver
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/middleware/driver/sys_ctrl/sys_ps_driver.c#L91-L119>`_
  explicitly documents 1=reset release and 0=reset, despite the opposite
  HAL comment. The model follows that driver contract and states its reset
  boundary separately.
* `PRRO configuration generator
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/tools/env_tools/beken_utils/scripts/ppc.py#L45-L103>`_
  consumes 55 privilege and 70 security Reg/Bit mappings from BK7258

  payload, then padding the output to 1024 bytes with 0xff.
  The inspected source does not show the consumer's MMIO write sequence;
  neither that serialization nor ``ppro_default.csv`` proves hardware byte
  offsets, POR values, locking or denied-access behavior. MPC bases and APIs

* `STAR core header
  <https://github.com/Embracecactus/bk_avdk_smp/blob/4ca389311a7ef641f10b94d298dc07ee16b0f79c/cp/components/cmsis/CMSIS_5/CMSIS/Core/Include/core_star.h#L2332-L2363>`_

  ``EMSS_Type`` at lines 558--565 lacks padding matching its TCM offset
  comments, and several CACR masks at lines 956--983 reuse another field's
  position. A generic header is not a measured implementation identity.

* ``chips/bk7258/include/irq.h``, ``bk7258_console.h``, ``bk7258_amp.h``
* ``chips/bk7258/ap/bk7258_ap_smp.c``: running-vector handshake tokens
* ``chips/bk7258/common/bk7258_timerisr.c``: 32,000-Hz external reference
* ``tools/bk7258/_lib/layout.py`` and board-selected partition CSVs: XIP
  conversion and physical flash capacity

The NOR protocol/protection facts use GigaDevice's primary datasheet
`GD25WQ64E Rev1.2 <https://download.gigadevice.com/Datasheet/DS-00476-GD25WQ64E-Rev1.2.pdf>`_,
including tables 4/5. No datasheet text or vendor implementation is copied.

New model files are GPL-2.0-or-later. QEMU APIs and Cortex-M33 implementation
come from the existing QEMU base. This experiment carries no invented author
sign-off or claim of upstream acceptance.
